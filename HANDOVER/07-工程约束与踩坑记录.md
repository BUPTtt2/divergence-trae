# 07 · 工程约束与踩坑记录（改代码必读）

> 这些是长期调试沉淀的硬规则。**违反其中任何一条都可能复现历史 bug。** 按类别整理，含出处。

## A. 流程 / 状态机约束

1. **仪式阶段（起念/投钱/三变）绝不自动推进**：必须用户手动点按钮。绝不在 `useEffect` 或 `await delay` 后自动 `setPhase` 跳走。
2. `useGameFlow.js` 中有 `LOCKED_PHASES` / `LOCKED_AUTO_PLAY` 集合，勿删。
3. **变量必须先声明后使用**（useGameFlow.js：`keywords`、`qType`、`userInput`、`MAX_CLARIFY_ROUNDS`、`MAX_DEBATE_ROUNDS`），防 ReferenceError。
4. `setQinian` 必须同时支持对象式与函数式更新（`prev => …`），否则投铜钱计数不增加。
5. SSE 连接在 `sessionId` 变化时必须关闭，避免跨会话污染。
6. 澄清阶段 SSE 事件必须被 `clarifyActiveRef` 拦截，防状态抢占。
7. `ls_` 前缀会话（本地降级）跳过 SSE 订阅。

## B. UI / 布局约束

8. **任何透明/全宽/高位 z-index 容器都可能挡住右下角按钮**：容器用 `pointer-events:none`，只在真正可交互子元素上开 `pointer-events:auto`；仪式卡片 z-70 > 底部导航 z-55 时尤其要查。
9. 底部导航条为**右下角窄条**（`fixed z-[55]`，`right:24, bottom:18`），不横贯全宽，避免遮挡中央。
10. 仪式卡片容器要 `maxHeight` 限高 + 内部滚动（`overflowY:auto`），否则高内容上顶到顶部 ProcessStepper / 下压到导航条（P1-P3 栏与流程栏重叠即此因）。
11. `ClarifyDialog` 必须定义 `handleSkip`（防 Promise 悬挂），响应式 `maxHeight: clamp(40vh,58vh,70vh)`、`width:min(720px,94vw,calc(100vw-24px))`。
12. Agents 页需 sticky 顶部栏带「返回推演」按钮（带 `state.snapshotSid/label` + `sessionStorage 'resume_session_id'`，刷新后仍可见）。
13. 智囊卡片头像统一 24×24；订阅按钮 38×20 物理开关，独立 onClick + `stopPropagation` + `preventDefault`。
14. 所有含"Enter 提交"的输入框要处理 composition（`event.nativeEvent.isComposing`），防中文输入截断。
15. `3D 特效`：`DestinyRevealFX` 必须返回 `<group visible={false}>`；`YaolinesFormation` 返回空 group（用户明确删掉空中棍状模型）。仪式阶段保证「演」字与八卦台可见。

## C. 内容 / 文本约束

16. 所有日志/总结文本必须过 `sanitizeLLMText()`，移除 `<response>/<output>/<mention>`/【】等系统标签与未闭合标签。
17. 演总结文本：不得含【】、📌🎋☯✅等 emoji/图标，用阿拉伯数字序号 + 中文冒号，纯文字报告体，从真实对话提取关键词/立场，对话为空写"众智尚未发言"。
18. 命牌 6 段结构：卦 + 卦辞 + 择路 + 锦囊(3) + 禁忌(3) + 回溯(3 时间点)。内容必须个性化融入本次推演（用户问题切片/共识/分歧），不用纯预设。
19. 抉择阶段最多 3 个命牌选项，按 id 去重，每次进入 `branch_select` 重置 `choices`（`final.slice(0,3)` 覆盖写入），并重置 `fateRevealed=false`。
20. `sanitizeLLMText` 处理 mention 配对标签；`generateYanSummary` 入口对用户问题/智囊发言/后端结果各 `cleanTxt` 三次。
21. 智囊/镜渊/演日志文字需去除【分歧】【共识】【盲点】等代码括号；内部前缀【你】改为"你："。

## D. 数据 / 后端约束

22. 长期记忆存 `localStorage 'yance_long_term_memories_v1'`（上限 30 条：question/questionType/choiceLabel/selectedAgentNames/fateSummary/fateKeyPoints/fateContent）。
23. CORS 中间件**手动 echo 请求的 Origin**（不用固定 env），带 `Cache-Control:no-store / Pragma:no-cache / Expires:0`。
24. 后端熔断：连续 3 次失败才标记不可用，30s 半开恢复。前端请求前查熔断，熔断则本地兜底。
25. 跨域埋点用 `fetch(keepalive:false)`，不用 `navigator.sendBeacon`。
26. Deliberation API 用相对路径走 Vite 代理，不硬编码 baseURL。
27. 后端路由顺序：固定路由在前，会话路由在后（含保留字检查）。

## E. 部署 / 构建约束

28. `vite.config.js` `base:'/'`（绝对路径），否则子路由 MIME type 报错。
29. three 生态合并进 `vendor-three` manualChunks。
30. 构建产物带时间戳文件名防 CDN 缓存；部署后需强刷验证。
31. Vercel 需 `outputDirectory: dist`。

## F. 性能 / 超时约束

32. 上下文拼接到 LLM ≤480 字，超限截断。
33. 超时层级：`apiClient 6s < race 8s < 外层 12s`；`generatePersonalizedCardContent` 内部 3s/3s/5s。

## G. 沟通 / 工作方式（对用户）

34. 用户偏好**中文、简洁、给结论**；不要废话、不要"预设模板垃圾循环"。
35. 用户要求自主完成任务、只在需要权限时用选择题工具告知；追求"全赢"，拒绝无效小修改。
36. 改 UI 后**务必实测点击**（按钮能不能点到、有没有被挡、栏有没有重叠），因为这类 bug 只能靠跑起来验证，静态看不出来。

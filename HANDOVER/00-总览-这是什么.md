# 00 · 总览：这是一个什么项目

> 给下一个 Agent 的第一份阅读。10 分钟读完全貌，再看后面的编号文档。

## 一句话

**演策（Yance）** —— 一个「赛博算命 · AI 决策推演沙盘」Web 应用。用户输入一个纠结的决策（如"要不要接那个新 Offer"），系统按道家仪式流程（起念 → 投铜钱 → 装卦 → 召智囊 → 多智囊辩论 → 演总结 → 立卦 → 三变定局 → 生成命牌），把"占卜仪式感"和"多 Agent 辩论"结合，帮用户把重大决策想清楚。

## 它解决什么问题 / 产品定位

- 不是"算命"，是"决策推演"：用卦象做仪式外壳，用多个智囊 Agent（不同决策视角）做内容内核。
- 命签（命运卡）即传播载体：推演结束生成可分享的 PNG 命签，自带水印，分享即获客。
- 30 天回访是数据飞轮：事后回填结局，用于校准后续推演的准度。

## 核心体验路径

```
首页 → 推演台(/sandbox) → 输入问题
     → 仪式: 起念数字(P1) → 六投铜钱(P2) → 装卦(P3) → 用神校准(P4) → 三变定局
     → 演析问/澄清 → 遴选智囊 → 多智囊辩论 → 演总结
     → 抉择(branch_select) → 揭示命签 → 收藏/分享
```

## 技术栈（重要，先记住）

| 层 | 技术 |
|----|------|
| 前端 | React 19 + Vite 8 + Three.js(@react-three/fiber) + Framer Motion + Tailwind |
| 后端（主） | Express + Railway（`server/` 目录） |
| 备用后端（不启用） | Hono + Cloudflare Workers（`worker/` 目录） |
| LLM | 智谱 GLM-4-Flash（走后端 `/api/yan/chat/stream` 流式） |
| 部署 | 前端 Surge（`yance-bagua.surge.sh`）/ Vercel 备用；后端 Railway |

## 架构哲学（本项目的"魂"，改代码前必读）

1. **Harness 优先于模型**：不换更强 LLM，把"编排层"做厚。
2. **本地降级永远兜底**：任何 LLM / 后端失败，都有一条前端 localStorage 模板兜底，**永不白屏**。
3. **上下文预算控制**：前端拼接到 LLM 的上下文 ≤480 字，超限截断，400 时降级重试。
4. **双重状态锁**：仪式阶段（起念/投钱/三变）**绝不自动推进**，必须用户手动点按钮；绝不允许 effect 间接触发 `setPhase` 跳走（这是历史最大 bug 源）。
5. **界面追求"仪式感 + 可读 + 可点"**：任何透明/全宽/高位 z-index 容器都可能挡住按钮，改动 UI 时要格外检查 pointer-events 与 z-index。

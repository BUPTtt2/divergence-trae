# 02 · 核心流程与状态机

> 推演流程的核心状态机在 `src/game/useGameFlow.js` 的 `phase` 状态。所有 UI 渲染、按钮、条件判断都围绕 `phase`。

## 一、完整 phase 清单

按体验顺序（含仪式阶段）：

### A. 仪式阶段（赛博立卦，P1-P4 + 三变）
| phase | 含义 | 如何离开 |
|-------|------|---------|
| `qinian_mind` | P1 起念数字（输 1-100） | 点「一念落数 · 起卦」`handleConfirmMindNum` → `qinian_tou` |
| `qinian_tou` | P2 六投铜钱（投满 6 枚） | 点「六投已定 · 装卦」`handleConfirmSixThrows` → `zhuanggua` |
| `zhuanggua` | P3 装卦日志（展示日志文本） | 点「卦已装成 · 校准用神」`handleConfirmZhuanggua` → `yongshen` |
| `yongshen` | P4 用神校准（选用神/默认） | 点「用神已定 · 开演」`handleConfirmYongShen` → `sanbian` |
| `sanbian` | 三变定局（一忌→二忌→三忌→一要→…→两径） | 「下一变」逐步 +1，最后「定局·揭命」`handleConfirmSanBian` → `casting` |

| phase | 含义 |
|-------|------|

## 二、关键流转（useGameFlow.js 行号依据）

- `handleStart`（约 1091-1152）：`setPhase('input')` → 落仪式种子 → **停死在 `qinian_mind`，绝不自动推进**（历史上曾 `await delay(4000) setPhase('analyzing')` 导致"填不了就跳到演问问题"，已删除）。
- 仪式：`handleConfirmMindNum → qinian_tou`(3170)；`handleConfirmSixThrows → zhuanggua`(3204)；`handleConfirmZhuanggua → yongshen`(3209)；`handleConfirmYongShen → sanbian`(3252)；`handleConfirmSanBian → casting`。
- 主流程：`casting/analyzing/summoning`(3291-3297) → `clarify_loop` → `agent_select`(1564) → `agent_debate`(2074) → `reflecting`(1912) → `summary`(1922) → `oracle_prompt`(2868) → `oracle`(2880) → `branch_select`(2911) → `path_reveal` → `committing`(2848) → `final`(2832)。

> 状态机代码里，绝大多数流转由 `handleConfirm*` / `handleUserAdvance` 触发，**严禁在 useEffect 里直接 `setPhase` 跳仪式阶段**。

## 三、双重状态锁（最重要约束）

仪式阶段（起念/投钱/三变）**必须用户手动操作**，绝不允许：
1. useEffect 恢复状态后自动推进；
2. 任何 `await delay(ms)` 后自动 `setPhase` 跳走。

`useGameFlow.js` 有 `LOCKED_PHASES` / `LOCKED_AUTO_PLAY` 集合，以及大量 `★` 注释强调此约束。改动时**保持此约束**。

## 四、底部导航按钮（_renderNavButton，Game.jsx ~504）

- 每个阶段有一个"下一步"主按钮，住在**右下角固定窄条**（`fixed z-[55]`，`right:24, bottom:18`）。
- `mk(label, onClick, primary, disabled, title)` 生成按钮。
- 仪式阶段按钮：
  - `qinian_mind` →「一念落数 · 起卦」
  - `qinian_tou` →「六投已定 · 装卦」
  - `zhuanggua` →「卦已装成 · 校准用神」
  - `yongshen` →「用神已定 · 开演」
  - `sanbian` →「下一变」→「定局 · 揭命」

> ⚠️ 右下角按钮易被居中仪式卡片的透明容器挡住（z-index / pointer-events 问题）。修 UI 时见 [07](07-工程约束与踩坑记录.md)。

## 五、顶部流程条（ProcessStepper）

- `src/components/board/ProcessStepper.jsx`：顶部居中显示 立卦→召唤→析问→诸智→梳理→抉择→定论 七节点。
- `getCurrentIndex(phase)` 把当前 phase 映射到某节点（仪式 phase 会归到 0=立卦）。
- 与仪式卡片内的 P1-P4 步骤条是**两套不同步进**：顶部是"全流程"，卡片内是"立卦仪式内部步骤"。改动时注意区分。

# 03 · 仪式阶段、三变 / 两径逻辑说明（含用户疑问的答案）

> 本文件专门回答：**"一忌到两径有啥用？勾选什么？两径内容是预设的吗？和用户的问题有什么关系？"**

## 一、仪式阶段的整体定位

仪式（P1-P4 + 三变）不是"真正的算法"——**它是产品体验层的"仪式壳"**，用来：
1. 制造"天机参与决策"的沉浸感；
2. 把用户的**问题 + 心念数字 + 六次投钱**变成一串种子（`seed`），用于唯一化这次的卦象、签号、命牌，让"这一卦只属于这一次推演"；
3. 从 `seed` 推导出**卦象（64卦之一）+ 动爻 + 六亲/用神**，这些会成为后续命牌、演判断、两径的视觉/文案素材。

真正"算命判断"的内容是 `src/game/cyberRitual.js` 里用**确定性规则**（不是 LLM）从 seed 和问题类别算出来的。

## 二、三变（sanbian）是什么

三变是仪式最后一段：**七步承诺仪式** —— 一忌 → 二忌 → 三忌 → 一要 → 二要 → 三要 → 两径。

每步的 UI 是一张卡片，内容来自 `buildSanBian(question, gua, agents)`（[cyberRitual.js:436](file:///Users/yegua/vibe/个人Trae赛/divergence-trae/src/game/cyberRitual.js#L436-L535)）。

- **三忌**（`banPool`）：针对问题类别，给"三件别做的事"。例如情感类：
  - 忌在吵架后 24h 内说分手/求和
  - 忌翻手机查聊天记录
  - 忌为了证明自己花远超能力的钱
- **三要**（`doPool`）：给"三件今天/近期就要做的小事"。例如情感类：
  - 今晚 10 分钟不带手机写"最舍不得什么"
  - 3 天内约共同朋友聊半小时
  - 写 3 条不能妥协的底线
- **两径**（`twoPaths`）：给 **A/B 两条行动路径**（见下）。

## 三、勾选到底有什么用？（直接回答）

**勾选是"自我承诺确认"，没有强制校验，不卡流程。**

看代码（useGameFlow.js）：
- `handleToggleSanJi` / `handleToggleSanYao`（3347-3368）：只是把 `sanJiChecked[idx]` / `sanYaoChecked[idx]` 在 `true/false` 之间翻转，**纯 UI 状态**。
- `handleSanbianNext`（3347-3352）：点「下一变」只做 `sanBianStep+1`，**完全不检查是否勾选**。

结论：**"下一变"无论勾没勾都能走**。勾选框的存在意义 = 仪式感的"我认可这条"的承诺动作，相当于"画押"。如果你觉得它"没有用、没有东西"，是因为：
1. 内容本来就是**预设模板**（见下）；
2. 勾选不产生任何后续影响（不参与命牌、不参与演判断）。

> 设计取舍：这是一种"行动承诺疗法"式设计（把决策拆成可执行的微小行动 + 自我承诺）。但它当前是**孤立的**——勾选结果没有写进命牌、没有进入演总结、没有进入两径。这是可改进点，见 [08](08-待办与下一步交接.md)。

## 四、两径内容是预设的吗？（直接回答：**是的，是模板**）

`twoPaths` 的 A/B 是**写死的模板**，不是 LLM 实时生成，也不是从用户真实对话/智囊发言中提取的。

生成逻辑（[cyberRitual.js:471-519](file:///Users/yegua/vibe/个人Trae赛/divergence-trae/src/game/cyberRitual.js#L471-L519)）：
1. 用关键词匹配问题文本：`waterKws/travelKws/loveKws/jobKws/investKws/studyKws/moveKws`（如"游泳""旅行""分手""辞职""买""考研""搬家"）。
2. 命中哪类，就用哪套预设 A/B。例如命中"游泳"（waterKws）：
   - A = 今天/此刻就去（附 4 条安全前置条件）
   - B = 改日再去（附观察条件）
3. 若问题**同时命中类别**，且用神 topic 匹配，则用专属文案；否则落到通用兜底（`人生决策`）。
4. 最后把 `卦名+动爻` 拼进 standpoint（如"（☰大有卦·第3爻动）…"），让人能对上卦。

所以：
- **内容**：预设模板 + 卦名标注 + 关键词粗匹配。
- **个性化程度**：只到"问题类别"粒度（游泳/旅行/情感/工作/投资/学业/搬家），**不到"这句话具体怎么说"的粒度**，也没用智囊辩论/用户后续输入。
- **这解释了为什么你问"要不要游泳"，能看到「今天去」vs「改日去」**——因为代码里专门写了游泳关键词分支。

## 五、这些和用户问的问题有什么关系？（直接回答：弱相关）

关系链是：

```
用户问题 ──(关键词分类)──▶ 问题类别(topic: 健康/出行/情感/职场/财务/学业/家居/关系/人生)
                │
                ├──▶ 决定「三忌/三要/两径」用哪套预设模板
                └──▶ 决定「用神」(inferYongShenByQuestionType)
                │
用户心念数字+六次投钱 ──▶ seed ──▶ 卦象 + 动爻(唯一化, 每局不同)
                                    └──▶ 作为两径 standpoint 的卦名标注
```

**关联强度：中低。**
- 有相关：问题类别 → 模板选择；seed → 卦象唯一化 → 卦名标注。
- **没相关（缺失）**：两径/三忌三要内容**不读用户具体措辞的语义**，**不读智囊辩论结论**，**不读用户此前的澄清回答**，**不读用户最终选择**。
- 结果：同一个"情感类"问题，无论具体内容如何，得到的忌/要/两径文案几乎一样（只是卦名不同）。这正是用户感觉"没有用、没东西、和问题没关系"的根因。

## 六、结论与改进方向

- **现状定位**：三变/两径是"仪式化 + 类别化"的轻量内容，属于**占位/兜底**层，不承担真正的"AI 判断"。
- **用户真正想要的**：两径应针对**本次用户的具体话**（如"要不要游泳"）给出**明确、具体、可执行的判断**，并最好结合智囊辩论结论。
- **建议**（详见 [08](08-待办与下一步交接.md)）：
  1. 两径/三忌三要改由 **LLM 按"用户问题 + 卦象 + 智囊辩论摘要"生成**，LLM 失败再回落当前模板（保留兜底）。
  2. 把三变勾选结果写进命牌/演总结，让"承诺"有意义。
  3. 或在两径 UI 上标注"本选项由 X 智囊观点生成"，增强可信度。

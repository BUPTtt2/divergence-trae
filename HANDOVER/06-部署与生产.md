# 06 · 部署与生产

## 1. 生产地址

| 组件 | 地址 |
|------|------|
| 前端（主） | **https://yance-bagua.surge.sh** （验证入口：`/sandbox`） |
| 前端（Vercel 备用） | Vercel 项目代号 `divergence-trae` |
| 后端 | Railway：`yance-bagua-engine-production.up.railway.app`（老），当前以 Vercel 后端为主 |
| 后端 API 基址 | `https://yance-bagua-engine.vercel.app` |

## 2. 前端构建与部署

```bash
cd divergence-trae
npm run build                      # 产物 dist/
npx surge dist yance-bagua.surge.sh   # 发布 Surge（会同步生成 200.html）
```

- `vite.config.js` 的 `spaFallbackPlugin` 会在构建时把 `index.html` 复制为 `200.html`，保证 SPA 子路由刷新不 404。
- **产物文件名带时间戳**（`assets/[name]-[hash]-${Date.now().slice(-6)}.js`），发布后旧缓存自动失效——部署后**让用户强刷一次（Cmd+Shift+R）**。
- Vercel 部署：`vercel.json` 需配置 `outputDirectory: dist`。

## 3. 后端部署
- 常规：`cd server && railway up`（Railway）。
- Vercel：`api/` 与 `functions/api/` 作为 Serverless Functions 入口。
- 备用 Workers：`cd worker && wrangler deploy`（`wrangler.toml`，当前不启用）。

## 4. 本地联调
- 前端 Vite：`http://localhost:5173`（`/api`、`/health`、`/track` 代理到 `:3001`）。
- 后端 Express：`http://localhost:3001`。
- 前端本地预览入口：`http://localhost:5173/sandbox`。

## 5. 部署后必做
1. 强刷清缓存验证 `https://yance-bagua.surge.sh/sandbox`。
2. 走一遍核心流程：输入问题 → 仪式（起念/投钱/装卦/用神/三变）→ 遴选智囊 → 辩论 → 总结 → 抉择 → 命牌。
3. 确认无 429 崩溃、无按钮被挡、无阶段栏重叠。

## 6. 构建常见坑
- `base` 必须是 `'/'`（相对路径会在子路由下 MIME type 报错，见 vite.config.js 注释）。
- three 生态必须走 `manualChunks` 合并成 `vendor-three`，否则跨 chunk 引用出错。
- 改了 `Game.jsx` / `useGameFlow.js` 这类大文件后，务必 `npm run build` 验证编译通过（dev 不报错不代表 build 没问题）。

# 05｜自然对话分流与模型安全设计

## 1. 目标

系统应当解决用户提出的问题，但不应让所有问题承受同一套推演仪式。能力的体现不是“每次都召唤多个 Agent”，而是能判断何时直接回答、何时查询工具、何时需要澄清、何时值得启动多智囊推演，并在每条路径上给出及时、可验证的价值。

本设计替代“输入问题后强制建立四字段案卷”的入口。固定问卷、固定最少轮数和把短答按字数登记为事实的逻辑不再保留。

## 2. 问题复杂度不是能不能回答

复杂度只决定执行预算，不决定是否响应。系统从六个维度判断需要多重的处理：

1. 事实是否明确；
2. 结果是否高风险或难以撤销；
3. 是否存在多个互相冲突的目标；
4. 是否依赖实时信息或外部工具；
5. 是否涉及多人、长期影响或连续行动；
6. 当前未知是否足以改变建议。

系统采用五条执行通道：

| 通道 | 典型输入 | 首次响应 | 后续流程 |
| --- | --- | --- | --- |
| 直接解答 | `1+1 等于几`、概念解释、简单计算 | 直接给答案 | 不建案卷、不召唤智囊 |
| 轻量选择 | `要不要去游乐园`、今晚吃什么 | 先给判断框架或临时建议 | 仅在必要时补 0-2 个问题 |
| 事实查询 | 天气、价格、政策、行情 | 说明准备查什么 | 调用工具，标注来源与时间 |
| 深度决策 | 租房、职业、产品方向、关系选择 | 复述处境并给出初步抓手 | 动态案卷、多智囊、证据与分岔 |
| 安全响应 | 医疗急症、自伤、违法请求、隐私风险 | 优先处理安全边界 | 限制能力、提供安全替代路径 |

当输入不是决策问题时，系统不得为了展示推演流程而强行进入 Sandbox。

## 3. 对话入口

新增“对话接待 Agent”，负责一次完成：

- 识别用户想要答案、建议、查证、倾诉还是完整推演；
- 判断是否可以直接给出第一份价值；
- 将用户原话、明确事实、推测和未知分开；
- 选择执行通道和预算；
- 生成最少且最有信息增益的下一步。

首次回复必须包含至少一项即时价值，可以是直接答案、临时判断、可执行动作或明确的分析框架。禁止只回复调查问题。

对“要不要去游乐园”，合理的首次回复是：

> 这通常不需要完整推演。若今天精力尚可、有人同行，天气与排队也能接受，就值得去；否则改期成本很低。你现在最犹豫的是精力、同行、预算，还是天气排队？

对“1+1 等于几”，响应为“2”，流程结束。

## 4. 动态追问协议

问题数量为 0 到 N，不设最低轮数。

- 没有阻断未知：不追问；
- 只有一个主导未知：问一个；
- 有 2-3 个彼此独立且共同决定结果的未知：在一个自然对话回合中成组询问；
- 后一问题依赖前一答案：逐步询问；
- 用户已给出足够信息：直接停止；
- 用户表示不耐烦、要求结论或信息增益已经很低：带着明确未知继续。

每个候选问题必须通过“答案是否可能改变建议、智囊选择或工具任务”的检查。不能改变任何后续行为的问题不得展示。

用户可以自由输入一段话回答多个事项。系统从同一段话提取多项事实，不要求用户按表格逐项填写。

## 5. 回答理解状态机

每次输入只能落入以下状态之一：

- `confirmed`：能与当前问题建立明确语义关系；
- `partial`：获得部分信息，剩余内容继续列为未知；
- `ambiguous`：如“啥”“2”“看情况”，先解释问题或给具体选项；
- `correction`：用户修改前述事实，保留变更轨迹并以新版本为准；
- `refusal`：用户不愿回答，保留未知并继续；
- `off_topic`：回应新话题，不把内容写进旧案卷；
- `emotion`：先回应情绪，再判断它是否构成决策信息；
- `command`：如“直接说结论”“重新开始”“问宝宝智囊”，立即改变流程。

任何状态都不能仅依赖字符长度判断。模型不可用时，只允许将高置信度结构化信号写成事实，其余内容保持未知。

## 6. 模型路由、降级和成本

### 6.1 路由

1. 确定性计算、格式转换和已知规则由本地执行，不调用模型；
2. 轻量分类、JSON 提取和普通对话优先使用 `glm-4-flash-250414`；
3. 智谱出现 429、超时或结构错误时，切换 `deepseek-v4-flash`；
4. DeepSeek 的普通任务显式关闭 thinking；只有复杂汇总或冲突审查才允许开启，并使用独立预算；
5. 连续两次 429 后触发提供商熔断，短期内不再让每个请求重复等待同一失败；
6. 所有提供商失败时返回自然的有限能力响应，不生成伪事实、不启动伪推演。

### 6.2 预算

每次会话维护调用次数、输入 token、输出 token、延迟、缓存命中和估算成本。默认预算按执行通道分配：

- 直接解答：0 次模型调用优先；
- 轻量选择：1-2 次；
- 事实查询：1 次规划 + 必需工具 + 1 次整理；
- 深度决策：按实际智囊数执行，默认不超过 10 次模型调用；
- 超出预算：先压缩上下文、复用已有结果，再由用户确认是否继续深挖。

按照 DeepSeek 2026-08-09 官方价格，V4 Flash 缓存未命中输入为 1 元/百万 token，输出为 2 元/百万 token。一次约 1,000 输入、300 输出的普通调用约为 0.0016 元；一次 10 调用、每次约 2,000 输入和 500 输出的完整推演约为 0.03 元。真实成本必须由运行时 usage 累计，不以估算替代账单。

## 7. dflow `@security` 信任边界

### 7.1 密钥与供应商

- API Key 只能存在于服务端环境变量；前端、响应、埋点和 Git 不得出现；
- 当前会话中提供过的 Key 在正式部署前应轮换；
- 模型名使用允许列表，禁止由用户输入任意覆盖 endpoint 或 model；
- 日志记录供应商、模型、状态码、延迟和 usage，不记录 Key、完整提示词或模型隐式推理。

### 7.2 用户数据

- 用户输入是不可信数据，不得覆盖系统指令、工具权限或审批边界；
- 发送给第三方模型前做最小化，只携带当前任务需要的信息；
- 敏感信息不默认进入长期记忆；进入记忆前需要明确用途和用户控制；
- 推测必须带置信度并等待确认，不能伪装为用户事实。

### 7.3 工具与行动

- 工具使用允许列表和参数校验；
- 查询型工具返回来源、时间和失败状态；
- 任何外部写入、消费、发送或不可逆动作都需用户确认；
- 工具失败时保留未知，不允许模型编造结果填补界面。

### 7.4 滥用与资源

- 限制输入长度、并发、每会话调用数和输出长度；
- 429 使用退避、熔断和跨供应商降级，防止重试风暴；
- 同一动作使用幂等键，刷新和重连不得重复扣费或重复执行；
- 用户之间的会话、智囊、记忆和事件继续执行所有权隔离。

## 8. 舞台联动

舞台不再展示与流程无关的装饰。所有视觉元素都由真实事件驱动：

| 系统事件 | 舞台反馈 |
| --- | --- |
| 直接解答 | 罗盘轻转后展开答案，不进入七阶段仪式 |
| 识别犹豫 | 两到三个真实顾虑化为可点击轨道 |
| 获得事实 | 对应信息节点落入案卷并与来源连线 |
| 保留未知 | 半透明节点继续悬浮，不伪装为已确认 |
| 召唤智囊 | 智囊从市集或用户资产进入对应席位 |
| 智囊发言 | 席位、轨迹和右侧正文同步高亮 |
| 工具查证 | 工具符号从问题节点连到证据节点，展示来源状态 |
| 观点冲突 | 两条观点轨迹相交，用户可点开冲突依据 |
| 用户插话 | 推演暂停，输入内容进入对应智囊或全体队列 |
| 易经镜面 | 只映射已验证、未知、冲突和变化，不承担算命结论 |

桌面端使用主舞台加可收起伴行栏；iPad 小窗使用底部抽屉，任何阶段都不得遮住关键图形和主操作。减少动态模式下仍保留完整信息反馈。

生图只用于背景纹理、图标或角色资产；信息节点、连线、状态和交互必须由代码和真实事件生成，避免把静态图片当作功能。

## 9. 覆盖矩阵

实现必须覆盖：

- 算术、解释、闲聊、轻量选择、复杂决策、事实查询、高风险问题；
- 短答、反问、错别字、一次多答、答非所问、拒答、改口、前后冲突和话题切换；
- 模型 429、余额不足、超时、空输出、非法 JSON、流式中断；
- 工具无结果、来源冲突、权限失败和部分成功；
- 刷新恢复、重复提交、连续点击、跨用户访问和中途退出；
- 桌面、iPad 横竖屏、小窗、键盘弹出和减少动态模式。

## 10. 验收标准

1. `1+1 等于几`直接返回 2，不创建推演会话；
2. `要不要去游乐园`先获得有用回应，不出现通用四问；
3. `啥`不会成为事实，系统会解释上一问题；
4. 一段包含多个事实的回答可一次填充多个字段；
5. 用户说“直接给建议”后最多一次汇总调用，不再追问；
6. 智谱 429 后一次请求内切换 DeepSeek，熔断期间不重复等待智谱；
7. 模型全部失败时仍可结束轻量问题，不产生伪造的多智囊内容；
8. 每个可见舞台元素都能追溯到会话事件；
9. 密钥扫描、跨用户隔离、预算上限和幂等测试通过；
10. 埋点能够计算首次有效回应时间、无意义追问率、重复追问率、放弃率、降级率和单次推演成本。

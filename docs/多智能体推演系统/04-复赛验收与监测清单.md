# 04｜复赛验收与监测清单

## 1. 用户闭环验收

- 非决策问题直接作答，不创建推演会话；轻量选择先给即时价值。
- 同一个问题能根据回答生成后续依赖问题，而不是固定三问。
- 独立问题可同轮成组询问，依赖问题按前一回答生成；用户可要求直接给建议。
- 案卷同时显示事实、系统理解、未知和冲突；用户可以纠正。
- 用户能从推荐、我的智囊和市集中组合智囊会。
- 每位已确认智囊均有独立状态和完整贡献；自建智囊不得缺席。
- 单独追问只调用目标智囊；补充或纠正会回到案卷分析。
- 工具调用显示开始、接受或拒绝；未经查证的行情不得进入结论。
- 汇总覆盖全部智囊、共识、冲突、未知和反转条件。
- 路径之间具有真实差异，并给出可逆动作和止损条件。
- 易经镜面能解释六爻知识状态；最终命牌刷新后仍可恢复。

## 2. 稳定性监测

| 层级 | 关键指标 |
| --- | --- |
| 会话 | 创建成功率、恢复成功率、状态越界次数 |
| Agent | 分派数、启动数、完成数、失败数、超时、每席贡献门槛 |
| 模型 | 提供商、模型、输入/输出 token、估算成本、延迟、429、熔断、空输出、规则降级率 |
| 工具 | 工具名、查询、证据接受/拒绝、来源、时效 |
| 用户 | 首次有效回应时间、无意义追问率、重复追问率、跳过率、纠正次数、案卷确认、路径选择、最终完成率 |
| 视觉 | 首屏可操作时间、面板遮挡、iPad 视口溢出、WebGL 降级 |

## 3. 当前自动验证

- 服务端完整测试覆盖身份、会话、案卷、贡献门槛、事件协议、单席追问、证据网关、反思和命牌链路。
- 前端生产构建必须通过。
- Lint 的历史 warning 单独登记；本轮改动不得新增编译错误。

## 4. 线下展示前人工走查

先用“1+1 等于几”“要不要去游乐园”“啥”“直接给建议”验证分流和异常输入；再使用“北京实习租房”“是否接受 Offer”“即时饮食选择”三类问题执行完整流程，并用 iPad Safari 重复一次。测试期间保留 Network 中的 `start / plan / answer / confirm-case / execute / interject / commit` 请求和 Session ID，网络异常时使用演示视频兜底。

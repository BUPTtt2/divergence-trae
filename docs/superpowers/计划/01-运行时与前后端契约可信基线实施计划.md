# Stage 01 · Runtime 与前后端契约可信基线实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立可测试的 Agent Runtime 和前后端 Deliberation 契约基线，修复当前会阻断新主链的事件、幂等、超时、探活和 execute 数据契约问题。

**Architecture:** 保留现有 Express、React、Node `node:test`、PostgreSQL/本地 Map 和 SSE 技术栈，不引入队列、工作流平台或新状态管理库。用一个前后端共享的纯 JavaScript 契约模块冻结 request/response；AgentRunner 继续作为唯一 Agent 执行入口，但事件写入、actionId 幂等和取消语义必须真实可测。

**Tech Stack:** Node.js >=18、Express 4、React 19、Vite 8、原生 `node:test`、现有 Event Store/内存数据库。

## Global Constraints

- 本计划不把 `useDeliberationFlow` 接入 `/sandbox`；主链迁移属于编号 04。
- 本计划不修改 Three.js、仪式动画、命牌或旧 `useGameFlow` 业务行为。
- 后端 Session/Event 是未来业务事实来源；本计划先冻结契约，不同时维护两种新轨响应。
- 所有 mock/fallback 必须保留明确来源标签，不得伪装真实成功。
- 不信任时间戳生成的幂等键；同一用户动作必须携带稳定 `actionId`。
- 所有新增测试使用本地内存模式，不访问真实 LLM、真实工具或生产环境。
- 不覆盖或提交当前工作区中与本计划无关的用户修改。
- 每个任务独立测试和提交；上一任务失败时不进入下一任务。

- [ ] **Step 4: Implement the shared contract**

```js
export const DELIBERATION_EXECUTE_STATE = Object.freeze({
  CLARIFY: 'CLARIFY',
  REFLECT: 'REFLECT',
  ORACLE: 'ORACLE',
  FAILED: 'FAILED',
});

function nonEmptyString(value, field) {
  const text = String(value || '').trim();
  if (!text) throw new TypeError(`${field} is required`);
  return text;
}

function uniqueIds(value) {
  if (value == null) return [];
  if (!Array.isArray(value)) throw new TypeError('agentIds must be an array');
  return [...new Set(value.map(String).map((id) => id.trim()).filter(Boolean))].slice(0, 6);
}

export function createExecuteRequest({ actionId, agentIds = [] } = {}) {
  return { actionId: nonEmptyString(actionId, 'actionId'), agentIds: uniqueIds(agentIds) };
}

export function parseExecuteRequest(input) {
  return createExecuteRequest(input || {});
}

export function normalizeExecuteResponse(input = {}) {
  return {
    sessionId: nonEmptyString(input.sessionId, 'sessionId'),
    state: String(input.state || DELIBERATION_EXECUTE_STATE.FAILED),
    findings: Array.isArray(input.findings) ? input.findings : [],
    oracle: input.oracle || null,
    conflicts: Array.isArray(input.conflicts) ? input.conflicts : [],
    gaps: Array.isArray(input.gaps) ? input.gaps : [],
    replanned: input.replanned === true,
    reason: String(input.reason || ''),
    dynamicChoices: Array.isArray(input.dynamicChoices) ? input.dynamicChoices : [],
    masterSummary: String(input.masterSummary || ''),
    fallback: input.fallback === true,
  };
}
```

export async function probeDeliberationHealth({ fetchImpl = fetch, bases = [''], timeoutMs = 3000 } = {}) {
  for (const base of bases) {
    const controller = new AbortController();
    const timer = setTimeout(() => controller.abort(), timeoutMs);
    try {
      const response = await fetchImpl(`${base}/api/deliberation/health`, {
        method: 'GET', signal: controller.signal, headers: { Accept: 'application/json' },
      });
      if (response.ok) return { ok: true, base };

    finally { clearTimeout(timer); }
  }
  return { ok: false, base: null };
}

- No new framework is required; all tests use Node 18 built-ins and current Express app.
- Shared function names are consistent across Tasks 1, 4 and 5.
- `actionId` is stable per user action and is distinct from event timestamp.
- Concurrent duplicate actions share one in-flight Promise; cross-process durable idempotency is explicitly deferred and not claimed.
- Health checks are read-only.
- Existing dirty UI files are explicitly outside scope.
- This plan does not claim production readiness when Stage 01 completes; it only creates a trustworthy base for Stages 02–04.

# 自适应编排与伴行助手实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Sandbox 根据用户新回答重新判断信息充分性与推演深度，公开智囊分派理由，并以不遮挡舞台的伴行助手承载全部对话和中断操作。

**Architecture:** 后端把深度预算、信息字段、案卷充分性和智囊分派统一到 Planner 主链；快问仅提供受控字段模板，不再以“有过回答”作为 READY 条件。前端使用一个响应式 Companion Dock 承载追问、过程、案卷入口和推演插话，3D 舞台只在执行阶段挂载并为 Dock 重新构图。

**Tech Stack:** Node.js ESM、Node Test Runner、PostgreSQL/Neon、React 19、Vite、Framer Motion、React Three Fiber、CSS Media Queries。

## 全局约束

- 不新增 UI 或动画依赖，不迁移现有 React、CSS、Three.js 技术栈。
- 用户明确表达才是 `confirmed`；模型推断必须是 `inferred`，未知必须保留为 `unknown`。
- 快推演最多两轮对话，每轮可收集 2～3 个相关字段；达到轮次上限不等于信息充分。
- 快推演使用 1～2 位互补智囊；标准 2～4 位；深度 3～6 位。
- 所有舞台动画必须由公开 Session 事件驱动；不展示隐藏思维链。
- 桌面和 iPad 横屏使用 360～400px 右侧 Dock；竖屏 Dock 不超过 `42dvh`；主舞台至少保留 65% 可视面积。
- 不部署、不推送远端；本地验收通过并由用户确认后再处理 Vercel + Surge。

本轮额外修正了无模型环境的最终兜底：不再输出“听从本心”式空泛结论；饮食场景会复述用户确认事实，并给出可逆、可观察的三条行动路径。此项只保证规则降级质量，不等价于真实模型质量验收。

真实 PostgreSQL 验收期间发现并修复两个发布级问题：生产认证密钥长度不足导致匿名登录返回 `AUTH_NOT_CONFIGURED`；前端曾把 `/plan` 错误地绑定到 SSE 已连接状态，流连接延迟时会出现“Session 已创建但永远不规划”。生产环境已增加独立 `AUTH_TOKEN_SECRET`；前端现由待规划 Session 直接驱动业务命令，SSE 只承担事件回放与可视化。

智谱真实链路使用官方免费 `glm-4.7-flash`。该模型默认思考时会消耗现有短输出预算，因此路由层对它统一发送 `thinking.type=disabled`；同时显式关闭付费 `Embedding-3`，确保当前比赛体验链路不因记忆向量化产生费用。

# 07 · 事件实况台体验改造实施计划

## 目标

把隐藏的同步规划改为可观察的事件流程，让任务、智囊、发言和结果在桌面、iPad 与小窗口中持续可见，并恢复 Vercel + Surge 发布基线。

## 实施模块

1. Session 与规划解耦：新增立即创建与显式规划合同，保留旧入口兼容；前端拿到 Session 后先订阅事件再启动规划。
2. 事件投影与实况台：补齐会话/规划状态、任务、智囊、证据、分歧和最近活动投影；实况台用可读卡片呈现，不只显示计数。
3. 动画与流程：移除固定 2.5 秒、2 秒的伪进度推进；界面 phase 跟随服务端状态与真实事件；快进只影响动画。
4. 响应式布局：桌面保留侧栏；iPad 与小窗口改为带分页的底部抽屉；验证安全区、触控和无横向溢出。
5. 部署：清理 Railway/CloudBase 默认指向，验证 Vercel 健康与持久化约束，构建后发布 Surge 并执行生产 Smoke。

## 验证顺序

每个模块先写失败测试，再实现并跑定向测试；完成后运行后端全测、前端全测、production build、浏览器桌面/小窗/iPad 主链，最后验证 Vercel 与 Surge。

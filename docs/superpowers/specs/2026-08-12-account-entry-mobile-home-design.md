# 演策账号入口与移动端首页收敛设计

## 目标

在不要求评委登录的前提下，让匿名体验、可选注册、个人资料与后台管理员账号形成一条可理解、可操作的路径，并修复手机首页上头像不可点、登录注册含义不一致、弹窗被悬浮助手遮挡的问题。

## 已确认产品规则

- 评委和现场观众默认匿名进入，不以登录作为体验前置条件。
- 普通访客可以选择注册；注册后用于跨设备恢复与后续进入个人账号。
- 管理员使用一个已注册账号登录 `/ops`，后台不向普通访客展示注册入口。
- 悬浮助手负责当前推演、新开一局、导航与帮助，不再管理账号资料。
- 头像支持演策字印预设与用户图片；图片在浏览器压缩后保存，避免上传原始大图。

## 交互结构

### 顶部导航

顶部头像是唯一的“我的账号”入口。桌面保留紧凑头像，手机显示“我的”文字，避免头像字印与菜单图标混淆。手机菜单继续承载页面导航，但改为更紧凑的双列布局。

### 首页首屏

首屏维持“立卦开演”为主动作；“浏览剧本”和账号入口为次动作。账号入口根据状态显示：未注册为“登录 / 注册”，已注册为“我的账号”，加载时不可点击。点击后始终进入同一套账号资料界面，不再只打开一个无法切换到注册的登录框。

### 个人账号

个人账号弹层同时展示当前身份、账号操作、昵称、头像、主色、签名和推演偏好。匿名状态可升级或登录已有账号；已注册状态显示邮箱并允许登出。头像图片先在客户端缩放为小尺寸 WebP/JPEG，再通过受认证接口保存；网络失败时保留本机修改并明确提示未同步。

### 悬浮助手

移除“我与偏好”入口，保留“当前推演”“新开一局”等推演操作。助手层级低于所有对话框；打开账号或登录弹层时，助手不会覆盖或抢点击。

## 移动端布局

- 弹层使用动态视口高度与安全区，内容独立滚动，顶部和操作按钮均可到达。
- 首页三个首屏按钮在窄屏变为两列：主按钮占满一行，两个次按钮各占一列。
- 手机导航收紧左右间距，账号入口有文字标签，菜单按钮使用明确的汉堡/关闭符号。
- 账号弹层遮罩高于导航和悬浮助手。

## 数据与安全边界

- 不保存用户原始图片文件，只保存缩放后的 data URL；限制输入类型和文件体积。
- `PATCH /api/auth/me` 只允许当前 access token 修改自己的昵称、头像、颜色和签名。
- 服务端对白名单字段、长度、颜色格式和头像 data URL 大小重新校验。
- 注册、登录与后台管理员授权仍是两件事：注册成功不自动获得 `/ops` 权限。

## 验收标准

1. 手机和桌面点击顶部头像均能打开账号弹层。
2. 首页账号按钮在匿名、离线、已注册状态均进入正确界面。
3. 登录和注册可以在同一弹层内互相切换，错误信息可见。
4. 预设头像和上传图片都能预览、保存；在线账号刷新后仍可恢复。
5. 悬浮助手不再出现账号入口，也不会压住任何账号弹层。
6. 手机菜单高度明显缩短，首屏三个动作不拥挤、不溢出。
7. 匿名用户不登录也能开始并完成推演。

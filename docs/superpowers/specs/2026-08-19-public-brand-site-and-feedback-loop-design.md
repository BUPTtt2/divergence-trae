# 演策公开品牌站与反馈闭环设计

## 目标

将 `yanceai.online` 的根页面改造为面向未登录访客的公开品牌站，而不是把完整产品导航和功能列表直接暴露给第一次访问的人。访客应在首屏理解演策是什么、看到真实的推演方式，并可在不登录的情况下开始一局。

同时建立全站可用的第一方反馈闭环，让匿名访客也能低摩擦反馈，并让运营者在 `/ops` 中看到反馈、来源、未读状态和提交漏斗。

## 产品边界

- `/` 是公开品牌站，不使用产品工作区的全量导航。
- `/sandbox` 是真实推演工作区，允许匿名访问。
- 有进行中会话的用户看到“继续推演”，其他用户看到“开始推演”；两者都直达 `/sandbox`。未登录访客另有明确的“登录”入口。
- 每日运势、智囊阁、命签册、社区、日历和卦典属于产品内部导航，不再出现在公开站首部。

## 品牌核心

### 定位

演策不是算命工具，也不是通用聊天机器人。它是一个把现实纠结放入多视角推演，最终产出可行动决定与可回看命牌的 AI 决策沙盘。

品牌主句：

> 把一个纠结，推演成可行动的决定。

辅助句：

> 多位智囊从不同立场辩论、追问和探路，决定仍由你做。

### 标志系统

新的主图形称为“演门”：两组对向的三爻线条围合出中央决策路径，同时呈现“多方进入、一路定夺”。它不直接使用常见太极图或八卦素材，避免品牌被误认为占卜站。

统一输出：

- 横版标志：演门图形 + “演策” + `YANCE`。
- 竖版印记：用于命牌、分享图和活动物料。
- APP 图标：墨黑底、朱砂演门、一个金色决策点；不放小字。
- favicon：仅保留演门轮廓，在 16px 和 32px 下仍可辨认。
- PWA 图标：192px 与 512px，包含 maskable 安全区。
- Open Graph 分享图：1200×630，使用主句、演门和一个真实推演层次。

所有尺寸都从同一份 SVG 母版生成，不使用多个无关的临时图标。

### 视觉语言

- 保留演策的东方线索，但从“古籍页面”转向“现代决策仪器”。
- 背景以黑、冷灰和一种纸色为主；朱砂是唯一高饱和强调色，金色只用于结果和状态。
- 标题字体可保留书写感，产品信息、按钮和表单统一使用高可读字体。
- 不使用每个区块一张白卡的模板化布局，用舞台、路径、分层和对比建立节奏。

## 公开品牌站结构

### 1. 首屏：一个纠结如何被推演

首屏只保留品牌、主句、一句解释、主按钮“开始推演”和次按钮“看一局示例”。

右侧不放静态八卦大图，而是一个可读的真实推演缩影：用户问题被收进舞台，三位智囊从不同方向进场，争议被收束为两条路径，最后结成命牌。示例不调用真实模型，不产生 Token 成本。

### 2. 产品证据：看见过程，不看功能表

使用一段可控制的横向舞台展示四个变化：问题进入、智囊争辩、路径翻牌、命牌形成。每次滚动只推进一个状态，不使用大段空白和孤立大字。

### 3. 为什么不是普通聊天

展示三个真实差异：视角会相互质疑，用户会被追问关键事实，结果会保留完整路径。不展示未经验证的用户数、满意度或虚构客户标志。

### 4. 一局真实样例

只保留一个可展开的示例，而不是四张重复的预设卡片。访客可在“接受 Offer / 留在当前团队”的模拟路径中点两次，看到推演如何改变，然后进入自己的推演。

### 5. 隐私、记录与成本信任

简洁说明匿名体验、本机保存、登录后同步、运营指标不保存问题正文，以及高成本生成能力的配额边界。

### 6. 结尾行动

只保留一个行动意图：“开始推演”。页脚提供隐私、协议、运行状态和反馈。

## 动效系统

动效是品牌语言，但不得阻断使用。

- 入场：演门从分离的爻线收束成一个门，总时长不超过 1.8 秒，按钮不等待动画即可点击。
- 首屏舞台：问题、智囊、路径和命牌按有限状态循环，完成一轮后停在可读结果。
- 滚动：区块的状态变化由滚动触发，不用纯粹的淡入堆叠。
- 微交互：按钮、路径、示例节点和反馈选项有按压、聚焦和成功回应。
- 对移动端：使用更短距离和透明度动效，不运行高成本指针跟随或大面积粒子。
- `prefers-reduced-motion` 下取消循环、视差和快速位移，保留即时状态切换。

旧的 8.6 秒首访强制引导、鼠标光斑、重复浮印、空白超长流程段以及营销页全局助手全部移除。

## 反馈闭环

### 入口

- 公开站页脚和帮助区的“反馈建议”打开同一个“回批笺”。
- 推演结束后继续使用“有帮助 / 一般 / 没帮助”的上下文反馈。
- 只在明确错误或用户主动退出未完成推演时，展示一次“哪里卡住了”，不弹通用拦截问卷。

### 字段

- 类型：功能异常、操作困难、推演质量、命牌体验、账号与付费、其他。
- 反馈正文：最多 800 字。
- 联系邮箱：可选，不作为提交前提。
- 上下文：页面、来源入口、发布版本、设备类型、匿名/登录状态。
- 隐私：不自动上传问题正文、对话、命牌内容或截图。

### 后端

新建独立的 `feedback_inbox` 数据表与 `/api/feedback` 通用提交端点，不将非推演反馈伪装成推演会话。现有 `/api/feedback/:sessionId` 保持为完成推演后的上下文反馈。

通用反馈端点必须有：

- 服务端枚举、邮箱与字数校验。
- 按主体和网络指纹的短窗口与每日限流。
- 幂等键和短时间重复内容抑制。
- 蜜罐字段和最短填写时间检查。
- 不向访客暴露内部栈、表名或邮件配置。

### 运营后台

`/ops` 增加统一反馈收件箱：

- 未读、已看、计划处理、已处理和不采纳状态。
- 来源、类型、版本、设备和日期筛选。
- “入口曝光 → 打开 → 提交”漏斗。
- 无反馈时不只显示“暂无反馈”，而是显示最近曝光量、打开量、完成推演数与建议动作。
- 邮件通知默认使用每日摘要，只在高严重度功能异常时立即通知。

## 组件边界

- `PublicLanding`：公开站页面组装。
- `BrandMark`：唯一的标志母版和尺寸变体。
- `DeliberationHeroDemo`：零 Token 的首屏演示状态机。
- `ScrollDecisionStory`：滚动推进的四步产品证据。
- `FeedbackDialog`：全站可调用的无障碍回批笺。
- `feedbackClient`：校验、幂等键与提交状态。
- `feedbackInboxService`：通用反馈存储、去重与运营状态。
- `OpsFeedbackInbox`：运营查看和处理。

`PublicLanding` 不再继续膨胀为单文件千行组件，动效状态机、品牌图形、反馈和内容区块分离。

## 错误与降级

- 反馈提交失败保留用户已填内容，提供重试，不影响当前页面。
- 动效脚本异常时首屏仍显示完整文案和 CTA。
- WebGL 不作为公开站首屏的必要依赖。
- 品牌 SVG 在 CSS 失败时仍可辨认。
- 旧的 `yance:open-yanchat` 事件、注释掉的 YanChat 引用和无监听者逻辑全部删除。

## 验收标准

### 品牌与入口

- 新访客在 5 秒内能说出演策的主要价值。
- 首屏 CTA 在 390px 手机、1366×768 笔记本和 1920px 桌面上均不需滚动。
- 公开导航不出现产品内部全量功能。
- favicon、APP/PWA 图标、导航标志和分享图属于同一视觉系统。

### 动效与可用性

- 入场动画不锁定 CTA，滚动动画不制造空白页。
- 键盘、触摸、鼠标和读屏器均可使用反馈笺。
- `prefers-reduced-motion` 验收通过。
- 移动端不存在横向溢出、固定层遮挡或无法关闭的弹窗。

### 反馈与运营

- 匿名用户可以提交通用反馈，不需要伪造推演会话。
- 成功反馈在 `/ops` 中可见，默认为未读。
- 重复、超长、非法枚举、蜜罐和超频提交被服务端拒绝。
- 运营指标不包含用户问题正文或对话原文。

### 工程验证

- 前后端新增逻辑有针对性测试。
- 前端 lint、完整测试与生产构建通过。
- 后端完整测试通过。
- 本地桌面、本地手机视口、`yanceai.online` 和 Surge 备用域名分别验证。
- 部署产物与本地构建保持同源，不存在服务器上的单独修补。

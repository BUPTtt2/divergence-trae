# 演策公测真实性、账号风控与成本控制设计

## 目标与发布阶段

演策当前进入“受控公开公测”，允许匿名用户和注册用户真实体验，但不等同于无限量开放或完成商业支付。公测必须同时满足三条底线：用户看到的能力状态可证实、账号恢复不能被滥用、高成本模型调用具备用户级与平台级闸门。

发布 Gate 为 `CONDITIONAL`：真实性和风控改造通过自动化验证后可继续受控公测；支付回调、退款、主体审核、ICP 与真实付费验收完成前，不宣称商业正式上线。

## 能力真实性合同

系统状态分为三个互不替代的维度：

- `service`: `checking | reachable | degraded | unreachable`，仅表示演策后端是否可连接；
- `execution`: `idle | running | model | fallback | failed | rate_limited`，表示最近一次高成本工作结果；
- `provenance`: `model | rule_gate | retained_fallback | safety_fallback | unknown`，表示当前展示内容的来源。

`GET /api/deliberation/health` 不调用模型，因此只能证明 `service=reachable`，不得产生“真实模型链路可用”文案。澄清问题必须读取案卷分析的 `source`：模型参与时显示“模型补充 + 规则校验”，完全降级时显示“规则校验/安全保底”。HTTP 200、Vercel Ready、服务延迟和模型生成是四类不同证据。

## 账号恢复与认证风控

密码恢复继续采用邮件一次性链接。公开请求始终返回相同文案，不暴露邮箱是否注册；重置链接是身份凭证，因此重置页只填写新密码与确认密码，已登录修改密码才要求当前密码。

安全规则：

- 重置链接 30 分钟有效，验证链接 24 小时有效，仅可使用一次；
- 同一用户签发同用途新链接时，旧的未使用链接立即作废；
- 邮件和页面明确展示有效期、一次性和旧会话撤销规则；
- 密码为 10-128 个字符，拒绝常见弱口令；
- 重置成功和已登录修改密码后撤销全部 refresh session；
- 日志、分析和限流表不保存明文邮箱、IP 或 token。

认证端点使用 PostgreSQL 共享固定窗口，多维度同时生效：

| 操作 | 目标维度 | 网络维度 | 说明 |
| --- | --- | --- | --- |
| 请求重置邮件 | 邮箱 1/60秒、3/小时、5/天 | IP 10/小时、30/天 | 不消耗用户商业额度 |
| 请求验证邮件 | 账号 1/60秒、3/小时、5/天 | IP 10/小时 | 已验证账号不发信 |
| 消费认证链接 | token 摘要 5/小时 | IP 20/小时 | 过期、重放、用途错误均拒绝 |
| 登录 | 邮箱 10/15分钟 | IP 60/15分钟 | 统一错误，不永久锁死账号 |
| 注册/匿名升级 | 邮箱 3/天 | IP 20/小时 | 防批量账号 |
| 匿名身份创建 | — | IP 120/天 | 为学校/比赛共享网络保留余量 |
| refresh | token 摘要 10/小时 | IP 120/小时 | 防伪造与重放轰炸 |

限流响应返回 `Retry-After`。生产环境保护服务不可用时，认证写入与高成本动作拒绝；健康检查和公开读取仍可用。

## 模型与生图成本控制

成本控制分三本账：

- 商业权益：用户购买或运营赠送的画境/高级推演额度；
- 安全限流：防止单用户、匿名身份或 IP 重复调用；
- 平台预算：保护火山方舟、DeepSeek、Seedream 与邮件供应商的总成本。

模型调用保留实际 usage 记录，不保存 prompt/response。每个模型调用在访问供应商前按消息文本和 `maxTokens` 估算保守 token 预留，进入 PostgreSQL 原子预算窗口：默认单用户每天 60,000 预留 token、全站每天 600,000 预留 token，可通过环境变量调整。预算耗尽时返回/记录 `LLM_BUDGET_EXCEEDED` 并进入可见规则兜底，不继续轮询备用供应商。

推演高成本动作另外限制：每个主体每小时最多 6 次开局、12 次规划/回答、8 次智囊执行。Seedream 继续使用画境权益、每用户限流和失败返还，不因供应商失败扣除权益。

## 运营与隐私

`/ops` 增加：

- 模型调用、实际 token、usage 缺失、估算成本缺失；
- 模型成功率、规则兜底率及来源分类；
- token 预算使用量与预算拒绝次数；
- 按 scope 聚合的 429 次数；
- 重置/验证邮件请求、发送失败和成功；
- 画境请求、失败、返还与采用。

运营事件只保存 scope、结果、粗粒度阶段和匿名主体摘要，不保存问题、回答、邮箱、IP、token、模型正文或生成图片 URL。

## 用户体验

- 左上状态只显示“推演服务可连接/波动/不可连接”；
- 工作台当前批次显示“模型补充 + 规则校验”或“规则安全校验”；
- 重置邮件提交后显示通用结果、30 分钟有效期和重试冷却；
- 429 展示明确倒计时，不暴露账号是否存在；
- token 预算触发时说明“本次模型容量已达安全上限，当前问题由规则校验继续”，不得冒充模型结果。

## 验收

1. 健康接口返回 200 时，前端不出现“真实模型链路可用”。
2. 模型与安全兜底的澄清问题具有不同且真实的来源标记。
3. 同一账号新签发的链接使旧链接失效；过期、重放和用途错误均拒绝。
4. 邮箱、IP、token 和全站预算分别命中限制，响应带 `Retry-After`。
5. 登录、注册、匿名身份、refresh 和高成本推演均有分布式保护。
6. 全站预算耗尽后不访问模型供应商，并记录可审计的预算拒绝。
7. `/ops` 展示成本与风控聚合，不展示敏感内容。
8. 前后端全量测试、lint、build 通过；手机端完成重置链接、过期链接、规则兜底和正常推演验收。

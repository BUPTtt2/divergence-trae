# 演策复赛运营后台、行为分析与新推演入口设计

> 日期：2026-08-12  
> 状态：待用户书面审阅后进入实施计划  
> 实现基线：`/private/tmp/divergence-trae-agent-runtime-baseline`

## 1. 目标

这次改造解决三个相互关联、但权限边界不同的问题：

1. 评委或观众打开公开链接即可体验，不出现注册、账密或管理员入口。
2. 普通用户新开推演时保留自己的历史；共享 iPad 交给下一位时隔离上一位的本机身份与内容。
3. 产品负责人拥有一个私有运营后台，可以看到访问、漏斗、可靠性、反馈和版本变化，并据此改进产品。

本设计不采集用户的原始问题、案卷正文、智囊对话或命牌正文用于运营分析。

## 2. 身份与访问边界

### 2.1 评委和普通访客

- 公开体验链接继续允许直接打开。
- `AuthProvider` 在后台静默调用匿名身份接口，获得服务端签名的匿名访问令牌。
- 页面不显示登录门槛，也不要求评委输入账密。
- 匿名令牌只用于会话归属、隐私隔离、限流和埋点签名，不等于要求用户注册。
- 后端或匿名认证不可用时，页面必须显示真实的服务状态，不得把本地降级伪装成线上成功。

### 2.2 管理员

- 私有运营入口为 `/ops`。
- 管理员先通过现有正式账号登录，再由服务端读取 `ADMIN_USER_IDS` 白名单判断权限。
- 前端不存储管理密码、管理密钥或管理员名单。
- 非管理员访问 `/ops` 显示无权限或登录提示；直接请求管理 API 同样返回 403。
- 所有管理查询和导出动作写入管理审计事件。

### 2.3 为什么不让评委登录

评委体验属于低摩擦公开体验。账号登录会引入记忆成本、输入成本、密码安全和现场网络失败点，也会污染漏斗。管理员登录属于内部权限控制，不能与评委体验共用入口。

## 3. 新推演与共享设备交接

### 3.1 普通产品模式

悬浮助手在 `/sandbox` 内保持可见，并提供主动作“新开推演”。

- 已完成一局：直接创建新推演，保留当前账号和全部历史。
- 有未完成推演：确认“当前进度将作为未完成推演保留”，确认后创建新局。
- 不删除旧 Session、命牌、笔记或用户身份。
- 记录 `new_deliberation_requested` 和来源位置，不记录案卷内容。

### 3.2 共享现场模式

当 URL 或当前标签页启用 `kiosk=1` 时，同一悬浮入口的主动作改为“下一位 · 开新局”。

确认后：

1. 先尽力上报 `kiosk_handoff_started`；
2. 清除当前访客的本机身份、令牌、活动 Session、命牌、记录、笔记和智囊对话缓存；
3. 保留主题、音量等设备级设置；
4. 不删除服务端既有匿名 Session 和聚合事件；
5. 重载 `/sandbox?new=1&kiosk=1`，由系统静默创建新的匿名身份；
6. 第二位访客无法通过返回、刷新、命牌库或日历访问第一位内容。

当前左下角独立“下一位体验”按钮删除，避免与悬浮助手形成两个相似入口。悬浮助手收起状态也应直接露出清晰文字，不要求用户猜测图标含义。

### 3.3 失败处理

- 清理本机身份不依赖埋点成功；埋点失败不能阻塞交接。
- 清理完成后若匿名认证失败，显示重试状态，不恢复上一位的本机身份。
- 多标签页检测到共享设备交接时，其他标签页应失效或跳回新局，避免旧页面泄漏。

## 4. 第一方行为分析

继续复用现有 `product_events`，但把事件合同从“页面计数”升级为“以真实推演 Session 去重的产品事件”。

### 4.1 公共字段

每条事件只允许包含：

- `event_name`
- `principal_id`：服务端从令牌取得，不信任前端上送值
- `analytics_session_id`：一次页面访问周期
- `deliberation_session_id`：真实推演 Session，可为空
- `occurred_at`
- `release_id`：构建版本或提交指纹
- `mode`：`standard` 或 `kiosk`
- `device_class`：`mobile`、`tablet`、`desktop`
- `platform_family`：粗粒度系统/浏览器类别
- `properties`：事件白名单字段

不记录完整 IP、精确地址、用户原始问题、案卷正文、对话正文或命牌正文。

### 4.2 核心事件

访问与身份：

- `app_opened`
- `anonymous_identity_ready`
- `experience_entry_viewed`
- `kiosk_handoff_started`
- `kiosk_handoff_completed`

推演漏斗：

- `deliberation_started`
- `phase_entered`
- `phase_completed`
- `deliberation_completed`
- `deliberation_abandoned`
- `session_restored`
- `new_deliberation_requested`

可靠性：

- `llm_request_completed`：模型、成功/失败、耗时、是否重试，不含 prompt 和 response
- `fallback_activated`：规则、本地或离线兜底类型与阶段
- `artwork_request_completed`：成功/失败、耗时、错误码
- `client_error`：标准化错误码、阶段、版本
- `api_health_observed`：仅服务端或受控探测写入

价值行为：

- `destiny_card_saved`
- `destiny_card_shared`
- `outcome_revisit_submitted`
- `feedback_submitted`

### 4.3 去重与准确性

- 漏斗按 `deliberation_session_id + phase` 去重，刷新或恢复不会重复计算。
- 开始率以有效体验访问为分母；完成率以真实创建的推演 Session 为分母。
- LLM 和 Seedream 成功率优先使用服务端调用账本，不以浏览器单方面上报作为结算依据。
- 所有比例同时展示分子、分母和样本量，低样本量不展示趋势结论。
- 每个指标携带 `release_id`，允许比较发布前后，而不是只看累计总数。

## 5. 指标定义

### 5.1 访问与转化

- 独立体验人数：指定时间内去重的匿名或注册 `principal_id` 数。
- 访问次数：去重的 `analytics_session_id` 数。
- 推演开始率：创建真实推演 Session 的访问数 / 有效访问数。
- 推演完成率：进入 `final` 的推演 Session 数 / 已开始推演 Session 数。
- 命牌收藏率：收藏命牌的完成 Session 数 / 完成 Session 数。
- 分享率：发生分享的完成 Session 数 / 完成 Session 数。
- 结果回访率：提交结果回访的到期 Session 数 / 已到回访期的 Session 数。

### 5.2 漏斗与时长

- 各阶段到达人数与前一步转化率。
- 最大流失阶段及流失 Session 数。
- 完整一局 P50、平均值、P90 时长。
- 各阶段 P50、P90 停留时间。
- 恢复旧局成功率。
- 普通模式与 kiosk 模式分别展示。

### 5.3 可靠性与成本代理指标

- LLM 请求成功率、超时率、重试率、规则兜底率。
- Seedream 成功率、失败原因和 P50/P90 生成耗时。
- 前端错误会话率：出现阻断错误的 Session / 开始 Session。
- 各发布版本错误率与完成率。
- 模型请求数、输入/输出 tokens 和产品内估算费用；供应商未返回 usage 时显示“暂无可核对用量”。

### 5.4 反馈指标

- 有帮助 / 一般 / 没帮助的数量和占比。
- 问题标签分布。
- 反馈与阶段耗时、兜底状态、生图结果、设备类别和版本的关联。
- 低样本量时只展示事实，不生成“版本变好/变差”的自动结论。

## 6. 用户反馈

终局案卷增加轻量反馈，不弹强制模态框：

1. “这次推演对你有帮助吗？”：有帮助、一般、没帮助；
2. 可多选问题标签：问题没问到点、智囊重复、结论太泛、等待太久、操作不清楚、命牌体验、其他；
3. 可选文字建议，明确提示“请勿填写姓名、联系方式或敏感决策信息”；
4. 提交后显示简短感谢，不诱导评分；
5. 一局默认只提交一次，可修改但保留更新时间。

反馈正文只在管理员后台显示。事件表只记录评分、标签和反馈记录 ID；可选正文单独存储，便于设置权限和保留期限。

## 7. 私有运营后台 `/ops`

### 7.1 概览

- 今日、7日、30日独立体验人数、访问、开始局数、完成局数。
- 完成率、完整一局 P50/P90 时长、帮助率。
- 当前发布版本、后端健康、近一小时错误会话数。

### 7.2 漏斗

- 按真实流程顺序展示每阶段 Session 数和环比流失。
- 支持时间范围、普通/kiosk、设备、发布版本筛选。
- 点击阶段进入匿名 Session 列表，只展示时间、阶段、耗时、状态、错误码和降级类型。

### 7.3 质量与可靠性

- LLM、Seedream、API 和前端错误分栏。
- 按错误码、版本、设备、阶段聚合。
- 不在运营后台展示 prompt、模型原始回答或用户决策正文。

### 7.4 反馈

- 评分、标签、可选建议、时间、版本、模式、设备类别。
- 支持标记已读和内部备注；内部备注不返回访客端。
- 首版不做自动回复、工单系统或自动模型微调。

### 7.5 最近体验

用于现场判断系统是否正在工作，展示最近匿名 Session 的：

- 开始时间、当前阶段、已用时、是否完成；
- 模型请求与失败数；
- 生图状态；
- 是否反馈；
- 模糊化匿名编号。

这不是监控用户内容的“屏幕直播”。

## 8. 服务端接口

访客接口：

- `POST /api/track`：接收白名单事件，服务端覆盖身份字段。
- `POST /api/feedback`：创建或更新当前用户拥有的 Session 反馈。

管理员接口：

- `GET /api/ops/overview`
- `GET /api/ops/funnel`
- `GET /api/ops/reliability`
- `GET /api/ops/sessions`
- `GET /api/ops/feedback`
- `PATCH /api/ops/feedback/:id`

所有管理接口必须同时经过 `requirePrincipal` 与 `requireAdmin`。时间范围、分页、排序和筛选均由服务端限制，避免无界查询。

## 9. 数据模型与保留策略

### 9.1 `product_events` 扩展

增加可索引的分析 Session、推演 Session、版本、模式和设备类别字段。旧事件保留，但只在能够可靠映射时进入新指标。

### 9.2 `product_feedback`

建议字段：

- `id`
- `user_id`
- `deliberation_session_id`
- `helpfulness`
- `tags`
- `comment`
- `release_id`
- `mode`
- `device_class`
- `created_at`
- `updated_at`
- `review_status`
- `internal_note`

同一用户对同一 Session 只有一条有效反馈。

### 9.3 保留

- 原始产品事件默认保留 90 天。
- 聚合日指标可长期保留。
- 反馈正文默认保留 180 天，之后删除正文、保留匿名评分与标签聚合。
- 首版先实现可配置保留期限与清理任务，不在请求主链同步删除大量数据。

## 10. 安全与隐私

- 管理权限只在服务端判断。
- 管理员查询和反馈备注写入审计事件。
- 事件属性采用白名单，不接受任意前端 JSON 原样入库。
- 错误堆栈在写入前清理 URL 参数、令牌和疑似密钥。
- 反馈文本限制长度并按纯文本处理。
- 运营数据接口禁止返回邮箱、令牌、完整 IP、用户问题和对话内容。
- CSV 导出不列入首版，防止范围失控；确有需要时另行设计权限和脱敏。

## 11. 测试与验收

### 11.1 身份与权限

- 无账号评委打开正式链接后无需交互即可开始推演。
- 匿名用户请求 `/api/ops/*` 返回 403。
- 白名单管理员可以访问，移出白名单后立即失权。
- 前端隐藏 `/ops` 导航不能作为唯一权限措施。

### 11.2 新局与共享设备

- 普通模式新开一局后仍能访问自己的旧记录。
- kiosk 交接后第二位无法看到第一位任何本机内容。
- kiosk 服务端旧归档和匿名聚合仍存在。
- 清理、重载、匿名身份重建过程没有短暂显示旧内容。
- 多标签页不泄漏上一位 Session。

### 11.3 指标

- 页面刷新不会重复增加漏斗人数。
- 断点恢复不会被记成新局。
- 一局完整测试在后台恰好增加一次开始和一次完成。
- LLM/Seedream 服务端账本与后台统计一致。
- 筛选 release、mode 和 device 后分子分母正确。

### 11.4 反馈

- 反馈只允许提交到当前身份拥有的推演 Session。
- 一局重复提交执行更新而非新增。
- 普通用户不能读取其他人的反馈。
- 管理员可以筛选、标记已读和添加内部备注。

### 11.5 目标设备

- 比赛 iPad 使用真实 Wi-Fi 完成两位访客连续交接。
- 管理员在另一台设备实时刷新后台，能看到两局独立记录与正确漏斗。
- 整个过程中评委未遇到注册或登录页面。

## 12. 实施顺序

1. 收口匿名体验、管理员权限与共享设备入口语义。
2. 建立事件合同和数据库迁移，修正 Session 归属与去重。
3. 补齐推演、可靠性、生图和交接埋点。
4. 实现反馈存储与终局组件。
5. 实现私有 `/ops` 后台。
6. 加入数据保留和管理审计。
7. 完成自动化测试、浏览器测试和现场双人 iPad 验收。

## 13. 非本轮范围

- 不要求评委注册或登录。
- 不做用户内容回放、屏幕录制或热力图。
- 不把用户问题和对话送入第三方分析平台。
- 不自动根据少量反馈修改提示词、模型或业务逻辑。
- 不做完整客服工单、增长营销、A/B 实验平台或复杂 BI。
- 不把构建成功等同于线上数据链路和目标设备验收成功。

## 14. 已知风险

- 当前生产后端在国内网络的可达性仍是最高风险；埋点和后台不能弥补主链不可达。
- 生产运行副本与主仓库仍有漂移，实施应先在运行副本完成，再按交接规则单向同步。
- 旧 `product_events` 缺少部分新字段，历史趋势只能从新版本发布后形成可靠基线。
- 管理员首次使用前必须创建正式账号，并在服务端配置其用户 ID；这不影响评委匿名体验。

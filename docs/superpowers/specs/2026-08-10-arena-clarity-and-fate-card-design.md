# 推演台层级与命牌收口设计

## 目标

修复总结阶段 `oracle=null` 导致的白屏；让智囊工作台、推演记录、决策案卷和命牌成为互斥主内容；让用户能一眼区分模型生成与受控规则兜底；让命牌展示本局问题、选择、结论、行动和卦象，而不是空壳。

## 体验合同

- 同一时刻只展示一个主内容面。主内容打开时，3D 场景降为低亮、无标签、无连线、不可抢焦点的背景。
- 智囊工作台采用稳定的“顶部轮次 + 中部发言 + 底部输入”结构；数据到达只更新原位内容，不新增漂浮层。
- 推演记录是全宽阅读面，不与场景节点叠放；关闭后回到原工作面。
- 每条推荐路径和关键生成内容带一个不扩张布局的来源点标：`生成` 或 `兜底`，并提供可读的 `aria-label/title`。
- 最终命牌复用收藏页数据合同，至少包含问题、所选路径、汇总结论、三步行动、改路信号和认知镜面。卦象只作为约束视角，不替用户决定。

## 视觉方向

黑金底色保留，主强调色只用月白金；命牌正面以发光题字、六爻刻线、朱砂落印构成。动画只承担“凝聚、翻转、落印”三段状态变化，并尊重 reduced-motion。背景不新增位图资产，继续使用现有 Canvas/Three 纹理，避免额外加载跳变。

## 数据与错误处理

- 所有 oracle 入口先归一化，`null` 等同空对象，禁止读取 `null.primary`。
- 路径来源统一归一为 `model-generated` 或 `controlled-fallback`，旧字段继续兼容。
- 模型返回空路径时可以展示明确标记的兜底路径，但不能伪装为模型生成。
- 命牌内容不足时展示“资料待恢复”的明确状态，不生成假事实。

## 验收

- 自动化复现并覆盖 `createDecisionCard({ oracle: null })`。
- 自动化覆盖来源标签归一和记录/工作台打开时的 presentation mode。
- 定向 Node 测试、前端构建通过。
- 浏览器至少检查 1440×900、1180×820、1024×768：无文字穿透、无横向溢出、底部操作可达、总结到命牌不白屏。

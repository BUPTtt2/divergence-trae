# 演策「玄墨天象」视觉系统设计

日期：2026-08-10  
适用运行副本：`/private/tmp/divergence-trae-agent-runtime-baseline`

## 1. 目标

将演策从“暗色组件叠加的推演页面”重做为完整、克制、可辨识的周易决策体验。视觉必须服务真实推演状态：缺失信息、智囊到场、证据收束、路径选择、命牌归档，而不是用仪式动画掩盖运行逻辑。

本次必须解决：

- 命牌外观廉价、文字信息弱、放射线特效含义不清。
- 伴行栏过宽，压缩舞台并遮挡主要任务。
- 工作台存在多重滚动、元素互相叠压、内容突然出现。
- 页面之间字体、色彩、背景、卡片和动效缺少统一规则。
- “预设”字样破坏沉浸，同时真实模型和离线兜底又必须可追溯。

## 2. 视觉方向

方向名：玄墨天象。

- 主色：玄墨黑、温润骨白、旧金、极少量朱砂。
- 材质：黑玉、宣纸纤维、金箔压线、薄雾、旧铜氧化痕迹。
- 光源：统一从命牌或当前推演焦点向外扩散，不使用无来源霓虹光。
- 背景：山海雾气、暗金星轨、低对比卦纹；背景永远不承载正文。
- 字体：标题使用有书写感的中文字体，正文使用可长读的宋体，数字和状态使用等宽字体。
- 图像资产不得生成正文文字。问题、卦名、路径、结论和来源标记全部由代码绘制，保证清晰且与真实数据一致。

## 3. 命牌

### 3.1 结构

命牌由三层组成：

1. 生成式黑玉牌面底图：无文字，只包含可裁切纹理、边框和中央留白。
2. 程序化卦象层：六爻、卦符、星轨刻线，根据当前卦象生成。
3. 真实内容层：本局问题、结论短句、三项行动、模型来源和朱砂印记。

### 3.2 动效

- 移除当前四周放射线和高亮光球。
- 入场：牌体从阵台升起，墨雾沿边缘退散。
- 揭示：六爻从下至上点亮，正面通过有重量的翻转出现。
- 完成：朱砂“演”印落下，触发一次短促纸尘，不持续闪烁。
- 待机：仅保留 2–3px 的缓慢浮动与低频边缘呼吸光。
- `prefers-reduced-motion` 下取消翻转和粒子，仅使用淡入。

### 3.3 信息规则

- 命牌必须显示本局真实问题摘要、所选路径和下一步行动。
- 空值不使用泛化文案填满版面；缺失字段直接收起对应区块。
- 来源标记仅在角落显示一枚小印：`灵` 为模型生成，`藏` 为离线兜底。
- 可访问文本提供完整来源说明；界面不出现“预设模板”“预设模式”。

## 4. 推演舞台与工作台

### 4.1 桌面布局

- 使用明确的两列 Grid：舞台 `minmax(420px, 1fr)`，工作台 `clamp(380px, 42vw, 680px)`。
- 只有工作台正文区域可以滚动；顶部标题、阶段导航和底部行动区固定。
- 舞台标签、智囊节点和命牌都受舞台容器裁切，不进入工作台区域。
- 新内容以 180–320ms 的分组淡入和轻微位移出现，不改变既有内容的位置。

### 4.2 工作台层级

1. 当前阶段与一句话说明。
2. 主任务：补充事实、查看判断、智囊对话、选择路径或揭示命牌。
3. 次级证据：案卷、过程、历史记录。
4. 固定行动区：只保留当前阶段真正可执行的 1–2 个动作。

禁止同时展示多个争夺焦点的主面板。

### 4.3 移动与 iPad

- 宽度低于 900px 时改为上下布局，舞台占 36–42dvh，工作台占剩余空间。
- 伴行栏改为底部抽屉，不覆盖固定行动按钮。
- 所有点击目标最小 44px，正文不小于 13px。

## 5. 悬浮助手“演印”

- 收起态为右下角 48px“演印”，显示一次低频墨晕，不持续跳动。
- 展开态为最多 420px 的侧页；桌面从右侧滑入，移动端从底部展开。
- 助手只展示当前阶段相关内容：续演、导航、案卷提示、回访提醒。
- 不复制工作台正文，不承载长篇智囊对话。
- 展开后舞台使用轻微降亮，不改变舞台和工作台的布局宽度。

## 6. 页面统一

统一覆盖：首页、推演台、智囊、命牌收藏、社区、日课、历法、辞典、法律与隐私页。

共享内容：

- 设计令牌：颜色、字体、间距、边框、层级、动效时长。
- 顶部导航和页面标题结构。
- 背景图像、宣纸噪点、焦点光和空状态。
- 按钮、输入框、筛选、卡片、抽屉、错误与加载状态。
- 文案词表：用户界面不出现 `preset`、`fallback`、内部字段名或英文分类标签。

智囊头像使用同一画风的东方人物侧影或器物化身，名称和观点由真实数据层提供，图像不嵌入姓名。

## 7. 图像资产

生成资产全部保存到 `public/assets/generated/xuanmo/`：

- `fate-card-surface-v3.png`：竖版黑玉命牌底图。
- `arena-celestial-v3.png`：宽屏山海星轨舞台背景。
- `page-wash-v3.png`：可平铺的宣纸墨雾背景。
- `advisor-*.png`：智囊头像系列，统一光向和构图。

PNG 保留为生成母版；运行时加载同名 JPG（82% 质量），将三张核心图的首屏传输量由约 6.5 MB 降至约 1.1 MB。

生成图像只作为氛围、材质和人物视觉，不承担功能文本。加载失败时使用 CSS 玄墨底色和程序化卦纹，保证产品仍可用。

## 8. 状态与真实性

- 真实模型结果显示 `灵` 印；离线兜底仅在实际触发时显示 `藏` 印。
- 兜底结果不可伪装为模型结果。
- 网络、模型或图像加载失败时，提供可恢复的内联状态，不弹系统警告框。
- 新内容到达时保留原位置并显示轻量到场提示，禁止整页突然重排。

## 9. 实施顺序

### P0：比赛核心链路

设计令牌 → 舞台和工作台布局 → 命牌图像与动效 → 演印助手 → 推演过程状态 → iPad 适配。

### P1：全站统一

首页 → 智囊 → 命牌收藏 → 社区 → 日课/历法/辞典 → 法律与隐私页。

P0 完成并通过浏览器验收后再进入 P1，避免全站同时改动造成比赛主链路回归。

## 10. 验收标准

- 1024×768、1366×768、1440×900 下无组件叠压、横向滚动或正文遮挡。
- 命牌上的问题、路径和行动来自本局数据，且长文本安全截断。
- 动效存在明确阶段含义；静止 3 秒后没有持续高亮干扰。
- 助手收起时不遮挡主操作，展开时不改变舞台结构。
- 用户可辨别模型生成与离线兜底，但界面不出现“预设”字样。
- 生成图像失败时仍可完成推演。
- 相关单元测试、生产构建和公网核心流程通过。

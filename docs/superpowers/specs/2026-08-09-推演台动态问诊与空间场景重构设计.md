# 推演台动态问诊与空间场景重构设计

## 1. 目标

把推演台从“固定路由 + 连续浮窗”收敛为一个可恢复、可解释、可中断的决策 Agent 体验：简单问题当场解决，值得推演的问题先形成可检查的案卷；每轮信息收集一次展示若干个互不重叠的关键问题，用户可批量回答、部分跳过或直接授权带着未知继续；新的回答必须重新影响下一轮问题与复杂度，不得回放预先排好的问卷。

## 2. 问题分流

分流采用“确定性门禁 + 模型语义判断 + 受控降级”三层，而不是只靠关键词或只靠 LLM。

1. 确定性门禁先处理算术、空输入、明显安全风险和必须查询实时信息的问题。
2. 对其余自然语言，由模型输出结构化路由：用户意图、决策影响、可逆性、涉及的人、约束数量、信息新鲜度和建议深度。
3. 模型不可用、超时或格式无效时，规则只负责保守降级；短句“要不要”不再自动等于“直接回答”，也不会通过拼接选项重新进入同一路由。

路由结果只有四类：直接回答、查证后回答、轻量推演、完整推演。直接回答页必须提供“继续深入”入口，但不得自动创建多 Agent Session。

## 3. 动态批量追问

案卷 Agent 每轮读取用户原问题、已确认事实、用户修正、授权保留的未知和冲突信息，再生成本轮问题组。

- 每轮最多 3 个问题，默认 2 个；同一轮问题必须覆盖不同的决策影响，不得语义重叠。
- 有依赖的问题不得提前出现。例如先知道候选城市，下一轮才能询问对应通勤和租金。
- 用户一段回答可同时覆盖多个问题。系统按语义抽取到对应字段，而不是把同一句答案复制给所有字段。
- 提交整轮回答后重新运行案卷分析，下一轮问题来自最新状态，不保存隐藏的固定问题队列。
- 如果关键事实已经足够，立即停止追问；不得为了达到题目数量继续问。

## 4. 未知不是待办清单

未知项是动态状态，不是一开始固定的问卷字段。用户补充新人物、新目标或新约束后，案卷 Agent 可以新增、合并、降级或关闭未知项。

未知分为三种：阻断判断、会降低置信度、仅供完善。只有“阻断判断”且用户未授权跳过时才阻止进入推演。用户可以对单项选择暂不回答，也可以按现有信息继续；后者会把未知写入案卷和最终结论的限制条件，而不会伪装成事实。

## 5. Session 自愈

- 页面恢复旧 Session 时，如果服务端返回 401 或 404，前端必须清除 URL、sessionStorage、SSE 游标和本地活动状态，并保留用户原问题回到可重新开始状态。
- 提交回答期间只允许一个请求在途；按钮禁用且重复点击不产生第二个请求。
- `SESSION_NOT_FOUND` 不得进入普通“重试同一请求”路径。界面提供“重新建立推演”，用当前问题和已确认回答创建新 Session。
- 后端身份恢复后仍然看不到旧 Session 时，明确区分“会话已过期”和“认证失败”，避免 401/404 交替重试。

## 6. 空间视觉

恢复原有 3D 八卦盘、卦象、粒子、光灵和智囊环绕效果，移除当前收缩圆环。场景中的可视对象必须对应真实状态：

- 已确认事实形成靠近中心的稳定金色签片；未知形成外圈半透明签片；用户刚补充的事实沿光路归入案卷。
- 本轮问题只在底部“问策卷轴”呈现，支持 1—3 个问题一起回答；卷轴展开时不遮挡八卦中心。
- 智囊入席时从对应方位点亮，发言时光路汇入中央；完整发言放在可选侧卷，场景只展示一句核心主张。
- 不再并列堆叠右侧面板、左下信息卡和节点详情。任一时刻只保留一个主要交互面。
- iPad 横屏保持上方约 62% 的场景与下方约 38% 的卷轴；竖屏使用底部半屏卷轴，内容内部滚动，页面本身不横向溢出。

## 7. 验收标准

1. “1+1 等于几”直接返回 2，不进入推演。
2. “要不要去游乐园”得到有用的简短回应，可选择继续深入；不会通过选项拼接形成死循环。
3. 多约束租房问题建立 Session，一轮出现 2—3 个不重叠问题；回答一段长文本可覆盖多个字段。
4. 用户跳过非阻断未知后能继续；新增事实会导致未知和下一轮问题重新计算。
5. 后端重启或旧 Session 失效后不重复提交，不出现无限 401/404；用户能一键重建。
6. 3D 场景无收缩圆环，事实、未知、追问和智囊发言都有清晰联动；桌面与 iPad 均无关键遮挡。

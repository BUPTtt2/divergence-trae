# 08 · 自适应推演深度与问题路由设计

## 1. 原则

M3 不是每个问题都强行召唤更多 Agent，而是系统能判断任务复杂度、风险和信息缺口，并选择合适的推演深度。对“要不要吃饭”运行四维规划和多轮辩论既慢，也会降低可信度。

## 2. 三档深度

| 深度 | 适用问题 | 体验 | Agent 配置 |
|---|---|---|---|
| 快推演 | 低风险、可逆、日常、信息很少 | 辨意 → 一轮收集 2～3 个关键字段 → 给一个可执行建议 | 主 Agent + 1～2 位互补智囊 + 规则审计 |
| 标准推演 | 有明确取舍、影响数周至数月 | 拆题 → 2～4 位智囊 → 分歧 → 路径选择 | 领域、挑战、综合/审计 |
| 深度推演 | 高影响、难逆转、多利益相关方 | 补证 → 多轮协作 → 风险审计 → 人工确认 | 3～6 位 Agent + 工具与审批 |

路由依据包括可逆性、影响时长、风险等级、外部事实需求、利益相关方数量、用户要求和信息完整度。用户可以提升深度；系统不能在没有理由时自动堆叠 Agent。

## 3. “要不要吃饭”的正确体验

系统先明确这是低风险日常问题，展示“快推演”。第一轮收集当前身体感受、距上一餐与大致摄入、此刻目标中的 2～3 个独立字段，允许用户在一句自然语言里同时回答。回答出现减脂、疾病、用药或情绪性进食等新意图时重新规划并允许升级深度。赛博算命作为“观察镜头”可以用节律、节制、身体信号等语言增强仪式感，但不能伪装成医学事实。

## 4. 验收

简单问题不进入冗长多 Agent 辩论；复杂问题不被压成一句模板；界面明确显示当前深度及选择原因；路由结果进入事件和审计记录，可被用户提升或纠正。

# 03 · 工具与证据网关设计

## 1. 目标

Stage 03 只解决一件事：Agent 获得的外部信息必须经过同一条可信链路，调用成功不再等于证据成立。

网关统一执行以下判断：工具是否允许、风险是否需要人工确认、实现是否真实、结果是否有效、来源和时间是否完整、内容是否含提示词注入。Planner、ToolProbe、ReAct 和 `/api/mcp` 不得再绕过网关直接把结果写入黑板。

## 2. 工具分层

| 类型 | 例子 | Agent 处理方式 |
|---|---|---|
| `live` | 搜索、股票、天气、汇率 | 成功且非空时形成 E2 外部证据 |
| `deterministic` | 薪资计算 | 形成 E0 计算结果，必须标注公式版本，不冒充实时政策 |
| `static` | 旧宏观快照、本地黄历 | 可返回参考材料，但默认拒绝进入当前事实证据链 |
| `mock` | 假翻译、假笔记 | 从 Agent 工具表移除，调用时明确拒绝 |

风险等级采用 R0-R4。当前 Runtime 只自动执行 R0/R1；R2 及以上必须返回 `approval_required`，不能先执行后补审批。

## 3. 统一输出

```text
Tool Request
  -> 工具存在与 allowlist
  -> mock / risk gate
  -> 参数校验与超时执行
  -> 失败和空结果判定
  -> 来源、时间、鲜度标准化
  -> 不可信文本清洗
  -> Evidence Envelope
  -> 审计事件
```

每次调用返回 `ok/status/tool/riskLevel/executionMode/evidence/error`。只有 `status=accepted` 且 `evidence.accepted=true` 才能作为黑板事实；失败、静态快照、mock、待审批都必须保留机器可读原因。

Evidence 至少包含：`id/level/kind/sourceName/sourceUrls/observedAt/freshness/summary/data/accepted/rejectionReason`。

## 4. Agent 接入规则

1. ToolProbe 和 ReAct 只调用 Evidence Gateway，并把证据元数据写入状态。
2. 提示词中的可用工具只展示 `agentAccessible=true` 的工具。
3. 黑板显示来源、鲜度和证据等级；拒绝证据只能作为失败观察，不能支持结论。
4. 网关写入接受、拒绝、失败或待审批审计事件；事件失败不改变工具判定，但必须记录日志。
5. 搜索摘要等不可信文本在进入 LLM 上下文前移除典型指令劫持语句并限制体积。

## 5. 本阶段边界与退出条件

本阶段不实现通用审批 UI、不把 E2 搜索升级成权威 E3、不更新宏观数据库，也不部署生产。

退出条件：mock 无法执行或出现在 Agent 工具表；静态数据不能冒充当前事实；错误/空结果不能标记成功；Planner/ReAct 均走网关；证据来源、时间、鲜度和审计可追踪；相关测试与构建通过。

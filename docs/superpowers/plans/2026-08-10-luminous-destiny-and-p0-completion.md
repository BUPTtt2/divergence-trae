# 发光命牌与推演台 P0 收口实施计划

## 边界

- 唯一修改源：`/private/tmp/divergence-trae-agent-runtime-baseline`。
- 保留现有顶部阶段状态栏，不改变其视觉样式。
- 命牌采用月白自发光、半透明玉质、金色细线、朱砂印的 Canvas/Three.js 动态视觉，不使用黄色纸张或暗色漆板。
- 保留当前用户改动，不回滚无关代码。
- 按用户要求不执行测试套件或人工验收；仅做静态代码检查。未经验收前不向生产候选版同步、不部署。

## P0 顺序

### 1. 会话与追问稳定性

- 审查会话恢复、追问规划、回答合并和案卷重建链路。
- 让追问轮数由信息缺口决定，并设置 2–4 个高信息量问题的稳定边界。
- 使用已回答事实、拒答和保留条件去重，禁止跨轮重复或近义复问。
- 明确“按现有信息继续”的降级路径，避免案卷—选智囊—追问循环错位。

### 2. 智囊编排与真实发言

- 推荐阵容根据案卷目标、风险、未知和智囊能力动态评分，不写死四人。
- “采用建议”只合并推荐阵容，不清空用户已有选择；至少两位智囊才能开演。
- 开演后智囊主动完成首轮独立判断，并在后续对话中读取本局案卷、自己的历史和被邀请者共享上下文。
- 单聊、群聊、`@` 增删参与者语义一致；不会把群聊缩成单聊，也不会把一位智囊的内容串到另一位。
- 输出保留结构化论证字段，但通过智囊人格、视角与语气生成自然表达。

### 3. 工作台层级与操作语义

- 维持“本轮判断 / 智囊对话 / 案卷与过程”三层，但同一时间只展开一个主面板。
- 案卷更新、更正和补充事实统一放进“案卷与过程”；本轮判断只负责查看结论、继续讨论、暂停和显式汇总。
- 禁止系统在用户未点击汇总时自动显示“进入结论”。
- 所有底部操作可点击、无遮挡，并给生成中、完成、失败和待补证状态清晰反馈。

### 4. 场景、连线与引导

- 恢复信息节点、智囊、证据、冲突和结论之间的可读连线，并用运动表达真实状态变化。
- 场景智囊使用发光文字印记与轻量头像符号，减少卡片框束缚和重叠。
- 点击智囊可打开完整对话工作台；首次出现提供明确引导。
- 侧栏与记录互斥展开，支持宽度调整且不阻断场景操作。

### 5. 发光命牌与终局一致性

- 重做 `DestinyRevealFX`：连线汇聚八卦、六爻点亮、月白玉牌凝成、翻面、朱印、归档。
- 场景命牌只呈现卦名、主判断、三项行动和印记；完整依据留在右侧档案。
- 命牌页提供新开一局、返回首页、查看命牌库、查看完整过程和收藏反馈。
- 收藏、命牌库、分享图和终局使用同一标准化数据契约；过滤内部参数名和技术标识。

### 6. 悬浮助手与可用性

- 只保留接到真实页面或真实本地数据的入口；移除空壳个人偏好和失效按钮。
- 在命牌页和空场景提供新开一局、首页、过程、记忆与智囊阁的明确入口。
- 处理窄屏/iPad 下的遮挡、滚动区域、固定底栏和侧栏宽度。

## 完成条件

- 代码层面完成上述 P0，并静态检查事件流、状态机和数据契约。
- 不执行测试、不声称浏览器验收或线上验收。
- 不同步生产候选版、不部署；等待用户确认后再进行发布阶段。

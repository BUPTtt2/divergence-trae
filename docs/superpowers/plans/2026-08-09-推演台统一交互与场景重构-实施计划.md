# 推演台统一交互与场景重构实施计划

## 目标

把推演台从多个互相遮挡的浮层，收束为一个可持续交互的多智能体决策空间：用户能看见系统如何理解问题、哪些信息仍不确定、为什么选择这些智囊、智囊正在做什么，以及结论如何落到命牌与后续页面。

## 实施范围

1. 信息采集：按问题域生成同轮不重复的成组追问，区分关键未知与可保留未知；仅关键未知阻塞推演。
2. 案卷与智囊：案卷可随时查看、补充、纠正；智囊接收已知事实和保留未知；标准推演至少选择三位智囊。
3. 场景交互：状态固定在场景中央，智囊工作记录收进可展开的统一侧栏；移除遮挡视野的大型悬浮发言卡。
4. 结果呈现：卷宗、路径、易经镜面与命牌使用同一套视觉语言，并提供回首页、命牌库和重新推演入口。
5. 响应式：桌面与 iPad 均保持主场景、侧栏和操作区的可读性，不出现按钮被助手遮挡或内容越界。

## 验收门槛

- “要不要考研”首轮出现三个互不重复、与考研决策相关的问题。
- 回答首轮后，关键事实足够时可以进入案卷确认；保留未知明确标为条件，不会阻塞。
- 案卷确认前可查看并继续补充；进入推演后可补充事实、纠正案卷、单独追问指定智囊。
- 标准推演至少选择三位智囊，推荐、官方、我的智囊和市集均可用。
- 场景中没有大型发言浮卡遮挡；工作记录可展开和收起；右侧栏在 iPad 不压缩主操作区。
- 最终命牌在场景中揭示，结果面板与命牌库风格一致，并可返回主页或命牌库。
- 服务端测试、前端模型测试和生产构建通过。
